Talk like no one's watching — because no one is.

01

How it works

No middle stop.

Most chat apps route every message through a company's server, and a copy can stay there. Talken has no message server at all.

YouWindows or Android
sealed · device to device
Your frienddirectly, over the mesh

A mesh, not a middleman

Every device joins Yggdrasil, an encrypted overlay network that gives it a cryptographic IPv6 address derived from its own key. Peers connect straight to each other over Netty — no relay, no NAT headaches, no IP exposure.

The server is a phone book, never a vault

A small Spring Boot API helps people find each other, recover their key, and holds messages for friends who are offline. It never routes a live conversation.

02

What you get

Everything. Minus the middleman.

Every feature you'd expect from a modern messenger — and several you won't find anywhere else — rebuilt on an architecture where nobody stands between you and the person you're talking to.

01 / identity

Your key is your account

No phone number, no SIM, no contact upload. A cryptographic key only you hold — your address on the mesh is derived from it. Nobody, not even Talken, can take it away.

02 / personas

Personas

Be several people, honestly. One name and photo for work, another for friends — each contact sees the you that you choose, and your whole chat list can switch persona in one tap.

03 / files

Gigabytes, at full quality

Movies, albums, whole project folders. Files ride through your own Google Drive, so a 4 GB video sends as easily as a text — no compression, no links that die in a week.

04 / groups

Groups with real roles

Owners, admins and members, enforced on every change — add, remove, promote, rename, delete — fanned out device to device across the mesh.

05 / whispers

Whispers

Because every group leg is its own encrypted channel, you can speak to part of a group without the rest ever receiving a byte — sub-groups, built into the crypto itself.

06 / channels

Public channels

One person posts, anyone follows — like a tiny newspaper, readable even without an account. Posts, media, posters and edits, served from the edge.

07 / calls

Voice calls, peer to peer

Opus audio over RTP, straight between the two devices. Ring the other person, or call silently. No STUN, no TURN, no relay, no media server — anywhere.

08 / video

Video, whenever you want it

There's no "video call" button: every call starts as audio, and either side can turn the camera on or off mid-call — negotiated up front, so it's instant.

09 / huddles

Voice rooms

Drop-in huddles: nobody is rung, members just see a "Join" banner, and the room lives as long as one person stays. Built end to end — launching with a later release.

10 / voice notes

Voice notes

Hold to record, release to send — over the same private route as everything else.

11 / threads

Replies & pins

Quote any message to reply to it, and pin what matters to the top of a chat — synced between both sides.

12 / presence

Presence that's never stored

Online and offline signals are tiny peer-to-peer state packets that are never written anywhere. If a peer can't be reached, the silence itself is the signal.

13 / offline

Never miss a message

Friend offline? Messages wait in a post-office box — up to 1,000 of them, for three years — and arrive the moment they sign in.

14 / backup

Your-own-cloud sync

History backs up to your own Drive as AES-256-GCM files you can restore on a new device. Nobody else can read them — including me.

15 / platforms

Desktop & Android

A Java 21 + JavaFX desktop app with its own Windows installer, and a native Kotlin + Jetpack Compose Android app with an encrypted on-device database.

03

Built, not assembled

Nothing to tap.

Most messengers are glued together from the same chat SDKs, push services and relay servers — and every one of them is a place to listen in. Talken has none of them. Where it matters, I wrote my own.

no chat SDKno Firebaseno WebRTC relayno STUN / TURNno message serverno phone numberno analytics

Messaging engine & wire protocol

One module that is both client and server, speaking a hand-designed wire format over direct TCP on the mesh — with scope-first dispatch for messages, control packets and state signals.

SIPS — State Info Packets

My own framework for real-time peer-to-peer state like presence: fire-and-forget, never persisted, never queued on a server.

OMDB — the offline mailbox

An offline-delivery system on my own server: it holds sealed messages for people who aren't online and hands them over when they return.

A calling stack

Signalling over the messaging engine, Opus over RTP, its own AEAD media encryption with key epochs — peer to peer, with no media server in the path.

An identity chain

Email + password is the single root of trust: Argon2id and PBKDF2 derive everything else, the private key is sealed before it ever leaves your device, and the OS keystore guards it locally.

Edge storage without an SDK

Channels and group archives talk to Cloudflare R2 through hand-rolled AWS SigV4 request signing — no cloud SDK pulled in.

A Drive library

A standalone Google Drive handler for desktop and Android — the reason Talken sends multi-gigabyte files without owning a file server.

A REST backend

Spring Boot services for discovery, key recovery and offline delivery — with their own client library shipped into both apps.

Custom where it matters, standard where it's proven: the cryptographic primitives underneath — AES-256-GCM, X25519, HKDF, Argon2 — are the battle-tested ones. Rolling your own primitives is how messengers get broken; building your own system around them is how they stay unwatchable.

04

The privacy story

Layer on layer.

Security isn't one feature — it's a stack. Here's every layer, with an honest status next to each.

  1. L1

    Encrypted mesh transport

    Every byte between two devices is encrypted end to end by the Yggdrasil network itself.

    live
  2. L2

    Sealed direct messages

    The text of every direct message is encrypted again, on top of the transport.

    live
  3. L3

    Encrypted on-device storage

    On Android, the whole chat database is one encrypted file per account (SQLCipher).

    live
  4. L4

    Proof without the key

    You prove you own your account with an Argon2 hash of your key — the key itself is never sent anywhere.

    live
  5. L5

    Encrypted cloud backups

    Backups in your own Drive are AES-256-GCM ciphertext, with an owner check that works without the key.

    live
  6. L6

    Whole-envelope encryption, on by default

    Every part of every message — replies, media references, captions, each group leg — sealed with X25519 + HKDF, fresh keys per session.

    in testing
  7. L7

    Pairwise group encryption

    A group message is really N direct messages, each leg sealed with that member's own pairwise channel — so member A can never read B's copy, leaving is just "stop sending", and whispers to part of a group come for free. Group keys rotate per epoch whenever someone is removed.

    in testing
  8. L8

    The moving-target cipher

    AES-256-GCM as the trusted floor, wrapped in a Feistel engine whose structure is chosen from 2¹⁵ = 32,768 configurations — so the shape of the cipher itself keeps moving.

    designed

Playground · layer 7

Watch a message take a random path

A toy that shows the idea, not the cipher. The real design keeps AES-256 as its floor — the moving layer adds to that, it never replaces it.

05

Beyond messaging

A platform. Not just an app.

Talken is designed to be built on — by other developers inside the app, and by operators running it headless.

talken extensions · mods

Mods, safely

Third-party extensions running inside Talken — new chat features, UI moments, even re-skinning the app. Untrusted by design and sandboxed, with one load-bearing rule: an extension never gets internet access, so it can never smuggle your messages out. Researched around a pure-Java WebAssembly runtime, so one mod runs on desktop and Android alike.

vision
talken daemon · cli

Talken, headless

A background daemon and command-line tool — talkend and talken — exposing every Talken operation over a local socket, the way Yggdrasil itself runs. For servers, bots and automation on machines the operator owns.

planned
06

Talken for Startups

A cloud made of its users.

The biggest idea in the ecosystem: turn the devices already running Talken into a decentralised cloud — database, storage and compute — the thing AWS does with data centres, done with the network that already exists.

DDBdistributed database

A mutable DHT with a controller that looks like a normal database: you give it database-style input, it translates that into key → value form underneath and reads and writes the DHT. Phones are full nodes because Talken runs all day; broadcast is gossip, not a tree.

designed
DSSdistributed storage

Push the maximum work onto each client itself — 100% peer to peer over Yggdrasil — with storage and auth resolved through the DDB's hash mapping. No storage servers.

designed
DCSdistributed compute

Users publish buckets — approved code snippets to run. A thin coordinator only remembers which devices are grouped together; it never runs anything. When device A is busy, it asks B to run bucket #A1 with this input; B returns the output instantly — or answers BUSY, and A tries C. A keeps a priority list of whoever has been most available, and stronger devices are lent to more nodes by weightage, earning a bigger share.

Sensitive stays home

Any bucket can be marked sensitive, and is never sent into the shared compute pool.

Private self-networks

A small startup can join its founders' and developers' own devices into a private network — and run hundreds of sensitive buckets at once instead of fifty.
