The story

Why Jctx

You open an AI chat to get help with your project, and before you can even ask the question you spend ten minutes pasting files and explaining your class structure. Then the AI suggests a class that doesn’t exist.

Jctx does all of that in one command. It scans the project and writes a clean, structured context.txt — every class, every field, every method signature, every Javadoc, KDoc and docstring, and your build files — then prints a dashboard of token counts, language split and the dependency graph. Paste it, ask your question, and get an answer that names the exact class to change, and why.

No config, no dependencies: just Python and a folder. It started as a tool for my own Talken codebase and is now on PyPI.

Everything it does

Every feature.

01

Whole-project context

File tree, build files, every class and interface, fields, numbered method signatures and all their docs.

Three languages

Java, Kotlin and Python — including mixed projects, with per-language percentages.

03

Token estimates

A total token count with a per-section breakdown, and which AI models’ context windows it fits.

04

Dependency graph

Which of your classes depend on which — from imports and in-body type references, no library noise.

05

Markdown or text

Plain context.txt by default, or a clean context.md with --md.

06

Slim mode

--slim keeps only class names and signatures, to save tokens on huge projects.

07

Clipboard

--clipboard copies the whole report, ready to paste.

08

.jctxignore

Build folders are skipped automatically; add your own exclusions in one file.
